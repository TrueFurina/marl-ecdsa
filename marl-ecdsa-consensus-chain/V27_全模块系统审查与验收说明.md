# V27 全模块系统审查与验收说明

## 本次修复的可复现问题

1. **账户隔离：** 首页原先未传入当前登录账户 ID，可能加载其他账户的最近一次训练结果。现改为按当前账户筛选；账户无训练数据时返回空状态，不使用全局历史结果填充。
2. **训练进程重启恢复：** Dashboard 重启后，若原训练子进程的管理对象丢失，历史任务可能永久显示 `running`。新增安全的结果文件恢复：结果 JSON 的模式、回合数和摘要字段满足预期时标记完成；无法找到存活进程且结果不完整时标记失败，允许重新训练。该措施不是任意 PID 的强制终止，长时间运行的跨进程任务仍需管理员检查。
3. **来源损坏后仍可审计：** 原页面仅列出 `eligible` 训练的历史链上记录，若贡献文件损坏/丢失就无法进入旧区块审计。现在可根据当前账户绑定的历史纪元和签名区块检索，仍能区分“证书有效、训练来源失败”。不会把来源失败误写成证书失效。
4. **参数边界：** BC-MARL 至少 2 回合才能参与治理；原表单允许 1 回合而治理必定失败。现限制为至少 2 回合，Pure MARL 仍支持 1 回合。
5. **展示一致性：** 修正旧版启动标题与页面不符、旧版登录界面静态测试中脚本版本缓存断言过时的问题。

## Windows / VS Code / CMD 使用与验收

1. 解压完整源码，打开 `source_code` 文件夹。此前 V26 的 `instance/`、`keys/`、`results/contribution/` 如需迁移，**先备份**，只合并原有真实数据，不要用空目录覆盖旧数据库。
2. 创建虚拟环境：

```cmd
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip check
```

3. 在 CMD 终端 1 启动后台：

```cmd
set PYTHONUTF8=1
set MARL_ECDSA_KEY_PASSPHRASE=此处改为自己的强口令
set MARL_ECDSA_REQUIRE_KEY_PASSPHRASE=1
.venv\Scripts\python.exe start_dashboard.py
```

4. 浏览器访问 `http://127.0.0.1:9090`：注册新账户、登录、退出、再次登录。验证错误密码拒绝、未登录 API 返回 401、登录页面 CSRF 校验、刷新页面后登录状态正常。网页返回空任务不是报错。
5. **协作训练：** 新建 BC-MARL / IQL / 3 智能体 / 30 回合 / 25 步任务，检查 `running → completed`、日志、奖励及合作率。可另外执行 Pure MARL 用于对照。没有产生有效优化批次时损失图可以标注无数据，不能伪造曲线。
6. **贡献治理：** 选择刚才完成的 BC-MARL 任务，检查训练来源摘要、贡献窗口和三个智能体的票权映射，确认与选中任务一致。
7. **可信共识：** 确认节点均停止，激活候选纪元。新 CMD 终端执行 `.venv\Scripts\python.exe run_consensus_nodes.py`，查看节点 `17401/17402/17403` 在线且纪元匹配。随后提交一次当前任务的签名存证。只有 `replicated` 才表示三个节点已返回写入回执。
8. **证据审计：** 按区块高度核验签名证书、跨节点一致性、训练来源以及纪元字段，确认 `verified=true`。再在测试副本上对贡献文件进行可恢复的变更或临时移走，确认旧证书仍有效、来源核验变成 `false`。**不要直接篡改唯一真实训练文件。**
9. **异常检查：** 故意停止一个节点，检查页面是否如实显示离线及复制不足；恢复节点后检查核验。重启 Web 服务，检查已完成任务可读，不能永久卡在 `running`。
10. 所有按钮点击后必须出现结果、成功提示或明确错误，不允许空白无反馈。浏览器 F12 检查 Console/Network，确认不出现未解释的 404、400、403 或 500。
