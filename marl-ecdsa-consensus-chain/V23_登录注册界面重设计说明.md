# V23 登录 / 注册界面改版说明

## 修改目标

保持 V22 项目原有账号系统、训练、贡献治理和共识接口不变，仅更新认证页的视觉设计与浏览器端交互。

## 本次变更

- `templates/auth.html`：新的响应式双栏页面。桌面左侧展示与主工作台一致的深青灰—青绿视觉及训练→贡献治理→加权共识→链上核验的流程示意，右侧提供登录/注册表单；手机自动改为上下结构。
- `static/auth.css`：使用与 V22 主页面最终样式相协调的深青灰 `#17282e`、青绿 `#0d9d91`、米白 `#f7f7f3`、暖橙 `#e99a73`；提供轻量节点浮动、连线流动、背景呼吸和入场过渡。尊重系统的“减少动态效果”设置。
- `static/auth.js`：密码显示/隐藏、Caps Lock 检测、注册密码规则提示、两次密码匹配校验和提交中状态。

## 安全及功能兼容

- 表单继续向 `POST /login`、`POST /register` 提交，与原后端认证路由完全一致。
- 保留 `username`、`password`、注册时的 `confirm`、`csrf_token` 字段以及服务端错误信息。
- 只增加界面上的即时输入反馈，真正的账号、密码、CSRF 校验仍由后端完成。
- 未改动 SQLite 用户数据、密钥、账本、训练任务或共识程序。
- 无远程字体、CDN 或外部依赖；视觉图形由 CSS 与 SVG 绘制。

## 启动方式（Windows / VS Code CMD）

1. 备份现有项目，尤其是 `instance/`、`keys/`、训练结果目录。建议在新目录解压完整 V23 包。
2. 使用 VS Code 打开 `source_code` 目录。
3. 首次安装依赖：

   ```cmd
   py -3.11 -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

4. 运行时仍使用项目原有密钥口令配置，不能随意更换旧密钥的口令：

   ```cmd
   set PYTHONUTF8=1
   set MARL_ECDSA_KEY_PASSPHRASE=替换为你的现有密钥口令
   set MARL_ECDSA_REQUIRE_KEY_PASSPHRASE=1
   .venv\Scripts\python.exe start_dashboard.py
   ```

5. 浏览器访问 `http://127.0.0.1:9090/login`。登录和注册页可通过上方标签切换；注册后用新账号登录，登录成功跳转至原工作台。
6. 如浏览器展示旧式样，请按 `Ctrl + Shift + R` 强制刷新静态资源。

**从 V22 覆盖升级：** 可只使用补丁包覆盖 `source_code/templates/auth.html`、`source_code/static/auth.css`、`source_code/static/auth.js`，保留原有 `instance/`、`keys/` 和运行结果文件不变。

## 验收记录与限制

- 通过 Jinja2 登录 / 注册模板渲染与字段检查，字段名、CSRF 标记、提交路径均保持一致。
- JavaScript 通过 `node --check` 静态检查。
- 使用 Chromium 对登录/注册页面分别检查 1440 / 1024 / 768 / 390 / 320 宽度，未发现横向滚动与页面脚本异常。
- 在 Chromium 中检查显示/隐藏密码、注册密码规则、确认密码不一致和匹配反馈，符合预期。
- 由于交付环境没有完整 Flask 运行依赖，**尚未执行实际账户注册→数据库写入→登录→工作台跳转的后端端到端测试**。需要在本地按上面的步骤再做一次功能验收。

## 建议的账户流程验收

- 进入 `/register`，注册符合规则的新账户：3–32 位 ASCII 字母、数字、下划线或连字符；密码 10–128 位，含字母与数字。
- 两次密码不同必须提示错误且不可提交；密码相同后允许提交。
- 注册成功应重定向 `/login`，并展示成功消息。
- 以错误密码登录应看到“账号或密码错误”；以正确密码登录应进入工作台。
- 退出登录后再次访问工作台应返回登录页。
- 按 Tab 可操作输入框、可见性切换按钮、提交按钮；开启“减少动态效果”后界面动画应关闭。
