# CCF 2026 竞赛演示中心（二次重构）

## 本次新增

- 「竞赛演示中心」：五层可点击架构图与功能说明。设计示意，不宣称已经实际部署所有节点。
- 原始账本检验：浏览器选择 JSON 文件，本地读取后提交本机服务 `/api/evidence/verify-ledger`，复算各区块哈希、链式引用、交易 ID、非创世块交易 Merkle 根；拒绝缺失已记录哈希和伪造数据。支持 2000 个区块、请求上限 8MB。
- 攻防结果：执行现有后端的消息篡改、重放攻击及拜占庭主节点测试，展示原始返回及错误，不预设通过。
- 一键答辩：手动四阶段引导；开始不会自动制造交易或攻击结果，防止混淆真实证据与演示流程。
- 证据导出：包括所导入账本的本次哈希校验结果、攻防测试原始响应和限制条件。

## 生成真实账本 JSON（仅在确实有已保存的账本时）

账本持久化文件必须是 `Block.to_dict()` 的区块数组；直接导入，**不要**导入 `/api/block_explorer` 的示意区块。

## 数据与安全边界

1. 文件校验只证明「提交给本机服务的记录相互一致」，**不是**公共网络链上确认，也**不是** ECDSA 公钥验签，不能证明共识最终性。
2. 页面使用已有实验后端接口，受控演示中触发攻击；后端接口目前依旧匿名可调用，不能直接公网部署。上线前需做登录鉴权、POST + CSRF、角色权限、审计和速率限制。
3. 进程当前为原始 Flask 本地服务，未配置生产 WSGI/HTTPS。
4. 若要证明真实分布式链共识，应进一步提供节点签名、交易收据、独立节点 RPC/持久化账本交叉对照、验证者公钥及共识证书。

## 启动

在 `source_code` 下执行 `pip install -r requirements.txt`，然后 `python start_dashboard.py`，打开 http://127.0.0.1:9090 ，选择「竞赛演示中心」。
