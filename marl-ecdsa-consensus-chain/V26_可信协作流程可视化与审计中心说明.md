# V26 — 协作贡献可信共识：流程可视化与任务级审计

## 一、设计调整

本版本在 V25 基础上，以真实 BC-MARL 训练任务作为唯一的业务起点，避免把训练图表、奖励积分和通用区块链浏览器并列展示：

| 页面 | 调整后职责 | 实际数据来源 |
| --- | --- | --- |
| 协作治理总览 | 查看当前账户有效训练任务数、已形成纪元的任务数、已发现签名存证的任务数和最近任务 | `GET /api/distributed/collaboration/audit` |
| 协作训练 | 创建并运行训练任务，写入训练结果和贡献文件 | 现有训练任务接口与训练日志 |
| 贡献治理 | 按选定任务和回合窗口读取贡献，显示智能体→节点的候选权重和摘要 | `POST /api/distributed/contribution/preview`（只读预览） |
| 可信共识 | 五阶段可交互数据流、三节点票权、ECDSA 签名与加权共识阶段、存证及追溯核验 | `GET /api/distributed/collaboration/task/<id>/lifecycle`、现有签名/治理接口 |
| 证据审计 | 历史任务索引、各纪元、已签名区块及独立在线核验 | `GET /api/distributed/collaboration/audit` 和 `/trace/<height>` |

原来的独立“节点诊断”不再是一级导航；真实节点状态直接出现在共识执行页，并保留“刷新节点状态”“跨节点验证”和故障恢复工具。原来的通用“安全实验”导航由“证据审计”替代，能够对真实协作任务执行链上与链下双层核验。独立积分公式实验室和登记簿静态统计展示从前端移除，贡献页现在以任务实际贡献与治理权重的映射为主。

**兼容策略：** 删除的是冗余的页面入口和视觉内容，并未执行数据库清空，也没有删除后端历史兼容接口或区块链账本。原有登录、训练和节点服务继续保留。

## 二、区块链实际作用流程

```text
当前账号成功完成的三智能体 BC-MARL 任务
        │ 任务 ID、配置、结果 SHA-256
        ▼
同任务的贡献日志 + 最近回合窗口摘要
        │ 校验后计算候选节点投票权重
        ▼
离线激活纪元化权重配置（必须停止共识节点并满足一致性要求）
        │ 纪元版本、训练绑定、节点权重、快照摘要
        ▼
生成结构化贡献存证事件 → ECDSA 交易签名
        │ PRE-PREPARE 事件、PREPARE 节点加权投票、COMMIT 节点写入
        ▼
有效票权证书 + 区块哈希 + 各节点本地账本
        │ 区块高度作为反向查询入口
        ▼
核验签名与证书 / 跨节点一致性 / 训练文件与贡献来源
```

流程图中已完成/未完成状态来自后台的真实任务读模型。仅在提交操作成功返回阶段事件时，页面才显示本次的真实投票数量、投票权重、写入节点数和返回状态；页面重新加载后不凭空重造历史投票事件，只展示能够从证书/区块验证的内容。

## 三、在 VS Code 中运行（Windows / CMD）

1. 备份旧项目的 `source_code`，尤其备份 `instance/`、`keys/`、`results/contribution/`。旧项目已有密钥必须配套保留相应口令。
2. 全新安装时：解压完整 ZIP，进入 `source_code`。原有项目升级时：解压补丁，覆盖 `source_code/templates/`、`source_code/static/`、`source_code/visualization/` 的同名文件，新增 V26 JS/CSS。无需删除旧数据库。
3. VS Code 打开 `source_code` 目录，在 CMD 终端运行：

```cmd
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
set PYTHONUTF8=1
set MARL_ECDSA_KEY_PASSPHRASE=你自己设置的强口令
set MARL_ECDSA_REQUIRE_KEY_PASSPHRASE=1
.venv\Scripts\python.exe start_dashboard.py
```

4. 浏览器访问 `http://127.0.0.1:9090`，先登录，并在「协作训练」中创建 **3 智能体 BC-MARL** 训练任务，直到数据库任务状态 `completed`、退出码 0、训练结果 JSON 和匹配贡献文件都产生。
5. 在「贡献治理」选择真实任务及训练回合窗口，检查候选节点票权和 SHA-256 来源。**预览不会激活纪元。**
6. 进入「可信共识」，使用页面顶部的同一训练任务。首先在全部共识节点停止的前提下预览并激活新的纪元权重；然后新开一个 CMD 终端执行：

```cmd
.venv\Scripts\python.exe run_consensus_nodes.py
```

7. 点击“刷新节点状态”确认本地三个实际节点 `17401`、`17402`、`17403` 在线且使用相同纪元；然后点击“提交当前贡献快照至多节点账本”。观察提交返回的实际阶段事件、投票权重和复制状态。
8. 仅在提交返回 `replicated` 后，才把本次交易标记为完成三节点复制；若返回 `partially_replicated`、`commit_unconfirmed` 或 `already_attested`，分别按原有状态处理，不要将这些状态误写为新一轮完整复制成功。
9. 在「证据审计」选择历史任务，按高度执行在线三项独立验证。只有签名证书、跨节点副本、训练来源和纪元字段全部匹配时，才认定该次验证闭环通过。

## 四、最终验收

| 模块 | 验收标准 |
| --- | --- |
| 协作治理总览 | 无任务时显示真实空状态及操作入口；有任务时显示真实数量和进度 |
| 协作训练 | 真实创建任务，BC-MARL 训练完成，结果和贡献文件可读 |
| 贡献治理 | 同一任务贡献摘要、最近窗口和三节点候选权重显示，不把积分称为链上付款 |
| 可信共识 | 五阶段互动、三节点状态、加权 PREPARE/COMMIT 响应、交易高度和来源核验状态正确 |
| 证据审计 | 历史任务读取范围为当前账户，按真实高度返回核验结果，离线/失败有具体说明 |

## 五、完成的检查与保留边界

- **23 项**回归/新增单元测试通过，包括独立 HTTP 共识节点、纪元配置约束、任务与训练文件绑定、账本存证、审计索引范围检查。
- 模拟接口浏览器交互检查：1440/1024/768/390 宽度下五个导航、流程图、三个节点、贡献预览、审计分层检查正常，页面脚本异常 0，未发现横向溢出。
- 空数据模拟验证：零训练任务时各页面显示解释性空状态，不填充假任务和假链上证书。
- **未完成：** 当前执行容器没有 Flask，未能对真实账户登录与数据库执行浏览器端到端验收。模拟数据用于浏览器自动化测试，**并未写入产品页面或交付数据库**。
- 本项目仍是三进程本地加权共识原型，不提供完整 PBFT 安全保证；贡献得分并非 Shapley 公平性证明；BC 积分不属于自动资产结算；来源文件哈希匹配也不证明训练本身客观真实。
