# MARL-ECDSA V22：任务驱动的协作可信共识工作台

## 1. 本轮目标

区块链功能的首要业务对象不再是任意文本交易，而是**由当前用户完成的 BC-MARL 协作训练任务**。训练任务 ID 贯穿结果文件、贡献记录、纪元化权重快照、ECDSA 存证交易、节点投票证书和跨节点区块核验。

本次保留 V21 后端已有的独立单机账本与通用交易作为辅助实验功能，不将它们称为分布式共识结果。

## 2. 数据流与参与模块

1. **训练模块**：`jobs` 表记录用户、任务、参数、状态及 JSON 结果路径。BC-MARL 生成含有 `run_tag` 与训练结果摘要的贡献记录。只接受已完成、正常退出的本账户任务。
2. **贡献模块**：从同一任务的贡献文件读取 `contribution_share`，限定三智能体，对最近 N 回合求平均，并采用 20% 均匀基础权重平滑和整数化；展示映射关系，不把 BC 积分当作真实资产。
3. **治理模块**：候选快照记录任务来源摘要、贡献文件摘要、节点映射、权重和纪元版本。仅在全部节点停止、账本一致且不存在未决投票时激活。
4. **链上模块**：从已激活的快照生成确定结构的贡献存证事件，以登录账户 ECDSA 密钥签名，经独立节点投票并写入区块。
5. **核验模块**：查询区块投票证书、对应纪元、跨节点区块哈希以及本地训练来源；区分链上证书有效与原始文件发生变化。

新的任务级查询接口 `GET /api/distributed/collaboration/task/<job_id>/lifecycle` 以登录用户权限为范围返回阶段状态、训练摘要、当前/历史纪元、已存证区块与最近一次校验结果，不在服务器端生成假数据。

新增**同任务/同快照防重复提交**检查。若某个区块已经包含当前任务的有效存证，再次点击会返回已有区块高度和交易 ID。节点不完整复制时应走恢复/核验流程，而不是再提交另一笔内容相同的交易。

## 3. 前端布局

「协作可信共识」页面顶部新增任务证据链工作台，选择 BC-MARL 任务后显示五个可核查阶段：协作训练、贡献记录、纪元治理、链上存证、交叉核验。下方保留原有的权重预览/激活、节点恢复、签名交易与区块追溯操作。旧单机账本和实验统计移至可展开的辅助验证区。训练与贡献页面可直接跳转到任务证据工作台。

## 4. VS Code 运行顺序

在 `source_code` 目录内先安装依赖 `python -m pip install -r requirements.txt`，分别启动 `python start_dashboard.py` 和 `python run_consensus_nodes.py`（需使用两个终端）。进入网站后，先完成 **3 智能体 BC-MARL** 训练。打开「协作可信共识」，选择该任务，检查来源、预览权重。**停止共识节点**、核验无未决投票后激活权重，再重新启动节点。最后提交贡献快照存证、点击任务证据刷新并核验相应高度。不要删除原有 `instance`、密钥和训练贡献文件；更换项目目录时应先备份。

如出现 HTTP 400，应在浏览器开发者工具 Network 的 Response 中查看真正的约束原因；不要禁用停机、同高哈希或未决投票校验。

## 5. 测试及技术边界

执行：

```text
python -m unittest tests.test_v22_collaboration_lifecycle tests.test_v21_collaboration tests.test_v12_consensus_invariants -v
node --check static/v22-collaboration-workbench.js
```

本轮的测试包含模拟训练数据的任务权限、纪元状态、真实三进程本机共识、链上回查及贡献文件修改后的来源核验。测试使用独立临时数据库。浏览器端到端测试仍需在具备 Flask 与浏览器自动化环境的机器上进行。

注意：本机三进程实验不等于跨服务器部署；贡献份额为奖励近似值而非公平性证明；持久化链上记录只能证明所提交摘要和签名的关联；该原型尚未构成经过形式化证明的完整 PBFT 协议，也没有进行真实代币结算。
