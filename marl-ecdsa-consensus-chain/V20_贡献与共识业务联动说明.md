# V20 贡献与共识业务联动

本次聚焦训练→贡献治理→链上确认的数据断点，不宣称完整 PBFT 安全。

## 实际业务闭环
1. 在协作训练完成 BC-MARL 并生成 `results/contribution` 记录。
2. 在可信共识页面预览贡献记录，检查 agent 到 node 的映射。
3. 节点停机且历史一致时激活权重快照，重新启动节点。
4. 点击「提交当前贡献快照至多节点账本」。后端**不接收任意前端伪造的权重内容**，而是读取当前已激活的纪元配置，核对映射和权重，构造标准 JSON 存证事件，由当前账户 ECDSA 签名并进入原有多节点加权提交流程。
5. 前端依据真实提交状态区分复制完成、部分复制、提交未确认和法定票数不足，并可在原有区块高度控件核验。

## 存证字段
网络标识、纪元版本、快照哈希、贡献记录文件 SHA-256、贡献回合数、智能体节点映射与权重、权重计算口径。完整原始训练日志不直接上链。

## 重要限制
- 当前训练评分为贡献份额代理指标，不是 Shapley 值；签名存证保证可核对记录，不保证贡献评价公平。
- 存证事件经多节点流程返回状态，不等于生产级拜占庭共识最终性。
- 协议仍为固定协调端和原有故障恢复原型。
- 不改原有训练、交易、浏览器、攻防功能。
- 目前没有完整 Flask 浏览器端到端联调，必须在本地启动 Flask 与三个节点复测。
