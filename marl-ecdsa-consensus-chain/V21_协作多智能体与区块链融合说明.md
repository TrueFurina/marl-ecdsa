# MARL-ECDSA V21：协作训练—贡献治理—共识存证闭环

作品名称：MARL-ECDSA共识链——面向协作多智能体的可信共识与激励机制

## 本版针对的问题

旧版中“训练任务”和“区块链权重”彼此松散：预览直接读取最近的任意贡献文件，不能证明该文件属于哪个登录用户、哪个已完成任务；链上交易虽然存证贡献文件哈希，却无法反查训练结果和激励积分。

V21 将该关系改为：

1. BC-MARL 训练成功后得到具体任务 ID、训练结果 JSON 和同 ID 贡献记录文件。新训练会在贡献文件中保存训练结果 SHA-256。
2. 登录用户仅能选择自己已成功完成、恰好有三个智能体、贡献文件与任务 ID 和回合数匹配的训练任务。
3. 按训练记录生成近似贡献份额，做非负裁剪、20% 均匀权重平滑，得到节点整数权重。同时提取 BC 积分承诺（仅记录积分，不代表链上资产发放）。
4. 预览绑定训练任务 ID、训练结果哈希、训练参数哈希、贡献文件哈希、所选回合窗口哈希、智能体与节点权重映射。
5. 关闭共识节点、核对账本一致、确保无未决投票后，激活下一纪元快照。**新纪元快照摘要将训练来源承诺纳入哈希**；不影响没有训练任务绑定的旧纪元哈希验证口径。
6. 共识节点重启后，“协作贡献存证”操作重新复算来源哈希、权重和积分哈希，生成结构化交易，由 ECDSA 签名并进入现有独立多进程加权共识。
7. 按交易所在区块高度回查：验证各节点区块/投票证书、所属历史纪元、交易事件内容与纪元权重、现存训练及贡献文件摘要。若训练文件被修改，证书仍可能为真，但 **来源校验失败**，不会显示为全链路验证通过。

特别说明：原有“通用交易输入”和“本地单节点账本”仍作为辅助对照，但作品主线是“协作贡献的可验证治理”，不是把通用转账功能作为创新点。

## 如何在 VS Code 的 Windows CMD 中运行

**先备份 V20 `source_code`，不要直接删除现有 `instance/`、`keys/` 和 `results/contribution/`。** 最方便的方法是在原 V20 目录中仅覆盖 V21 中的源码、模板、脚本与样式文件，保留已有用户账户和训练数据库。

1. 进入 `source_code`，在 CMD 运行 `python -m pip install -r requirements.txt`。确保启动网站和安装依赖使用同一个 Python 解释器。建议 Python 3.11。
2. 终端 1：`python start_dashboard.py`；登录后进入「协作训练」。
3. 完成一项 `bc_marl`、IQL、三个智能体的训练。训练结果应位于 `instance/training_logs/<任务ID>.json`；贡献记录应位于 `results/contribution/contribution_log_<任务ID>_<时间戳>.json`。
4. 进入「可信共识」，在“来源训练任务”中选择刚完成的任务，点击“读取训练贡献”，查看原始贡献、BC 积分和候选权重。
5. **停止节点进程**（如果之前已启动），检查三个账本一致、无未决投票。然后点击“激活权重快照”。如果存在历史未决投票，系统会拒绝切换，不应清除安全锁来掩盖错误。
6. 终端 2：`python run_consensus_nodes.py`。等待三个独立节点均在线且属于相同快照。
7. 点击“提交当前贡献快照至多节点账本”，看到实际区块高度后点击“核验区块与训练来源”。
8. 在测试副本中修改**已存证**的贡献文件，重新核验：`training_artifacts_match` 应变为 `false`（不得修改正式记录）。

如果改为全新目录运行，并希望继续用 V20 的训练历史，需同时备份并复制 `instance/business.sqlite3`、`instance/training_logs/` 和 `results/contribution/`，以及账户数据库、现有私钥等必要数据；本版对旧数据库中指向旧目录的绝对路径，只允许回退匹配当前目录内 **相同任务 ID** 的 JSON。不应复制含未知历史状态的 `quorum_v9` 到实验副本后直接强制激活。

## 可复核接口

- `GET /api/distributed/collaboration/jobs`：当前登录用户可用训练来源及不合格原因。
- `POST /api/distributed/contribution/preview`：`{"job_id":"任务ID","window":20}`。
- `POST /api/distributed/contribution/activate`：`{"job_id":"任务ID","window":20,"origin_sha256":"预览值","rounds_sha256":"预览值","training_result_sha256":"预览值"}`。
- `POST /api/distributed/contribution/attest`：当前活跃纪元的来源重新验证并上链。
- `GET /api/distributed/collaboration/trace/<height>`：按区块高度核验来源和节点结果。

所有上述业务接口均沿用网站登录会话；POST 请求需要 CSRF Token。操作必须按顺序执行。

## 测试结果与边界

- 本环境运行真实 `train.py` 三回合，生成训练 JSON 与带任务标识、训练结果哈希的贡献记录，成功读取候选权重和 BC 积分。
- 已运行 18 项协议与协作关联回归测试，包括独立三节点提交/跨节点核验、伪造/篡改后验证失败和历史纪元兼容性，均通过。
- 尚未执行 Flask 登录页面的浏览器端到端联调（当前环境缺少 Flask）；不能宣称页面所有控件已完成浏览器验收。
- 贡献评分基于局部奖励的归一化近似份额，不是 Shapley 值，也不能保证贡献评分公平。BC 积分是训练积分记录，并非链上自动结算的真实资产。
- 当前共识仍是固定协调端的三节点加权原型，缺少完整 PBFT 安全证明；本地回环多进程实验不能取代跨主机拜占庭安全实验。
- 快照一经确认，若训练结果或贡献文件被更改，重新来源审计将失败；这是一种可检测篡改机制，而非保证外部数据产生时已真实可信。
- 该 ZIP 未附带私钥或运行时 SQLite 数据库；旧项目的 `keys/`、`instance/` 应单独安全备份、谨慎迁移。

## 回归测试

使用无历史投票/空闲端口的独立测试环境：

```cmd
python -m unittest tests.test_v21_collaboration -v
python -m unittest tests.test_v11_epoch_view tests.test_v12_consensus_invariants -v
```

此测试会临时启动本地 17401–17403 节点端口；如同机已有节点进程运行，先关闭再测试。
